поэтому открываются прямо на GitHub — запускать ничего не нужно.

## Как они устроены

Ноутбук — плохой носитель истории изменений: JSON вперемешку с кодом,
выводами и метаданными даёт нечитаемые диффы и конфликты при слиянии.
Поэтому здесь принят подход «ноутбук как артефакт сборки»:

* повествование живёт в `sources/*.py` — обычный Python с разметкой ячеек
  (`# %%` и `# %% [markdown]`), который нормально читается в диффе;
* `.ipynb` собирается из него скриптом `scripts/build_notebooks.py`, который
  заодно **выполняет** ячейки и вшивает выводы и картинки.

Тот же приём известен как [jupytext](https://jupytext.readthedocs.io/); здесь
он реализован без внешних зависимостей, чтобы сборка проходила в CI, где
jupyter не установлен.

```bash
# пересобрать ноутбуки после правки исходников
python -m scripts.build_notebooks

# только проверить, что все ячейки выполняются без ошибок (используется в CI)
python -m scripts.build_notebooks --check
```

Править нужно `sources/*.py`, а не `.ipynb`: при следующей сборке ручные
правки в собранных файлах будут перезаписаны.
